# M5b — Polish & Deploy

Status: design
Date: 2026-05-01
Parent spec: `docs/superpowers/specs/2026-04-30-scrabble-design.md`
Predecessor: `docs/superpowers/specs/2026-05-01-m5a-snapshots-assist-log-design.md`

M5b closes out the polish pass and ships the game to Render. It is the final user-facing milestone before M6 (gamification).

## Scope

Five independent slices, intended to ship in this order:

1. **Animations** — flash newly-placed tiles, float a `+N` over the active player's card.
2. **Dictionary advisory** — replace the `checkWords` stub with a real Russian noun list and persist warnings on each move.
3. **"Новая игра" flow** — finished-screen rebuild + a server `newGame` action; a draw-for-order routine determines who plays first.
4. **Disconnect indicator** — small "не в сети" badge per player while their socket is closed; no game-pause phase.
5. **Deploy to Render** — `render.yaml` + production smoke test.

Each slice is independently shippable. Order is recommended but not required.

## Out of scope

- Full pause/`paused` phase + 5-min reconnect timer. Family use is wifi-blip-only; a badge is enough.
- Heavier animations (drag visuals, hover pulses, finished-screen winner reveal animations).
- Cross-game leaderboard, badges, achievements (M6).
- Mobile-specific layouts.

## 1. Animations

Two CSS-only effects, no protocol or store-shape changes beyond derived state.

**Tile flash.** When a `moveAccepted` arrives, the cells listed in `moveRecord.placements` get a brief highlight (yellow ring + slight scale) for ~1.2s. Implementation:

- Zustand store gains `lastPlacedCells: {row,col}[]` and `lastPlacedAt: number`, set when the snapshot's last event is a `MoveRecord` newer than what was previously flashed.
- `Square.tsx` checks whether its `(row, col)` is in `lastPlacedCells` and `Date.now() - lastPlacedAt < 1200`, applies a Tailwind animation class accordingly.
- New keyframe `tile-flash` defined in `client/src/styles/`.

**Score popup.** When a `PlayerCard`'s score increases, render a transient `<span>+N</span>` that translates up and fades. Implementation:

- `PlayerCard` keeps the previous score in a `useRef`; on render, if score grew, mount a span with key = `Date.now()` so React unmounts/remounts it cleanly.
- New keyframe `score-pop`.

**Suppression rules.**

- A `RevertRecord` (the most recent event being a revert) suppresses the flash.
- On reconnect / page load, if the most recent event's timestamp is older than 5 seconds, do not flash — the player is catching up, not witnessing a fresh move.

**Tests.** Visual; verified by running `npm run dev` and playing through. No Vitest assertions for the animations themselves.

## 2. Dictionary advisory

### 2.1 Word list

Source: [OpenCorpora](https://opencorpora.org/) dictionary (CC-BY-SA, machine-readable XML with POS + grammeme tags).

A one-time script `scripts/build-dictionary.ts` parses the dump and emits `server/data/nouns.txt` (UTF-8, one lemma per line, sorted, committed to repo). Filter rules:

- POS = `NOUN`.
- Excluded grammemes: `Geox`, `Name`, `Surn`, `Patr`, `Abbr`, `Trad`, `Init`.
- Lemma form is taken as-is (OpenCorpora stores noun lemmas in nominative singular by default).

Expected size ~100k entries / a few MB. Loaded into a `Set<string>` at server startup.

### 2.2 Lookup with substitution-aware normalization

Russian house rules allow Ё→Е and Ъ→Ь as one-way substitutions when *placing* a tile. Both forms (e.g., `ЁЛКА` and `ЕЛКА`) should resolve to the same lemma at lookup time.

Щ→Ш and Й→И are also one-way substitutions, but those are resolved at placement time — by the time a word reaches `checkWords`, the placed-letter form is already what's on the board. **No normalization** for Ш/Щ/Й/И.

Normalization applies only to Ё→Е and Ъ→Ь:

- At load time, build two sets: `nounsRaw` (lemmas as they appear in the file) and `nounsNormalized` (each lemma run through `Ё→Е, Ъ→Ь`).
- At check time: try the placed word against `nounsRaw`. On miss, apply the same `Ё→Е, Ъ→Ь` transform and try `nounsNormalized`. On miss in both, the word is unknown.

### 2.3 Persisting warnings

Add `dictionaryWarnings: string[]` to `MoveRecord` itself.

- Server populates it at move time (already computed; today it's only sent on the transient `moveAccepted` reply).
- The transient field on the WS reply stays for immediate placer feedback.
- `MoveLog.tsx` renders a "?" badge next to entries where `dictionaryWarnings.length > 0`, with the unknown words shown inline in a muted color: `КОТ +18 (не в словаре: КОТ)`.
- Past Games viewer inherits this for free.
- Persistence loader treats an absent `dictionaryWarnings` field on archived/in-flight `MoveRecord`s as `[]`, so existing JSON files keep loading.

### 2.4 Tests

`tests/dictionary.test.ts`:

- Known noun recognized.
- Unknown word flagged.
- `ЁЛКА` and `ЕЛКА` both valid when the lemma is `ЁЛКА`.
- Word with Ъ resolves both with and without the substitution.
- Proper noun absent (e.g., `Лев` is excluded by `Name` filter).

`tests/persistence.test.ts`:

- `MoveRecord` with `dictionaryWarnings` round-trips through save/load.
- Legacy `MoveRecord` without the field loads as `[]`.

## 3. "Новая игра" flow

### 3.1 Server action

After `endGame`, the server archives and sets `game = null`; seats stay populated. Add a new client message:

```ts
{ type: 'newGame' }
```

Handler:

- If `game !== null`, ignore (race: another player already triggered it).
- If not `allSeated(seats)`, reply `error: 'Не все игроки подключены'`.
- Otherwise: `new Game({ seed: Date.now() })`, `joinPlayer` for each seat, `startGame()`, save, broadcast — same shape as `server/index.ts:274-285`.

### 3.2 Draw-for-order routine

Replace the hardcoded `turnIndex = 0` in `startGame()` with a real draw. This applies to **every** new game, including the very first one.

Inside `startGame()`, before the 7-tile racks are dealt:

1. Each player draws one tile from the bag.
2. Compare tiles by alphabetical position (А=1, Б=2, …, Я=33). **Blank beats all letters** (treated as position 0).
3. On a tie, the tied players redraw between themselves until resolved.
4. All drawn tiles return to the bag, which is then reshuffled via `makeRng(seed)`.
5. The normal 7-tile deal proceeds. `turnIndex` is set to the winner.

A new event is appended:

```ts
type DrawForOrderRecord = {
  kind: 'drawForOrder';
  draws: { slot: Slot; letter: Letter | null }[]; // null = blank; one entry per player, in slot order
  firstSlot: Slot;
  timestamp: number;
};
```

Added to the `GameEvent` discriminated union in `shared/types.ts`. Always the first event of any game's transcript.

### 3.3 Client UI

- New `FinishedScreen.tsx`, rendered as a dimmed overlay when `phase === 'finished'`. Shows players sorted by final score (winner first), a "Новая игра" button (no confirm — finished is finished), and a "К списку игр" link.
- A client that reloads after `endGame` but before `newGame` sees the lobby snapshot (server has already nulled `game`), not the finished screen. This is acceptable — the just-finished game is reachable via the past-games viewer. The finished screen is "live only".
- `MoveLog.tsx` renders `DrawForOrderRecord` as the first entry: "Маша — А, Петя — К, Аня — М. Первой ходит Маша."
- Brief inline banner on game start (shown above the board, dismissable, auto-fades after the first move): same text as the log entry.

### 3.4 Tests

Engine (`tests/game.test.ts`):

- Fixed-seed `startGame` produces the expected `turnIndex` and `DrawForOrderRecord`.
- Bag size after `startGame` is 104 − 21 = 83.
- Tie-then-resolve: simulate a seed where two players draw the same letter, verify a redraw event is emitted and a winner is selected.

Server (`tests/server-newgame.test.ts` or extend existing):

- After `endGame` + `newGame`, snapshot is fresh (empty board, scores 0, new event log starting with `DrawForOrderRecord`).
- `newGame` sent twice in rapid succession results in only one new game.
- `newGame` while a game is in progress is a no-op.

## 4. Disconnect indicator

No `paused` phase, no timer. Just a UI badge.

- `Player` already has a `connected: boolean` field, set in `currentState()` from `seats[i].ws !== null`. Server already broadcasts on every connect/disconnect.
- `PlayerCard.tsx`: when `player.connected === false`, render a small grey dot + "не в сети" beside the name. Greys the card slightly.
- Reconnect-by-name already works (M4).

No engine changes. No tests.

## 5. Deploy to Render

### 5.1 `render.yaml`

```yaml
services:
  - type: web
    name: scrabble
    runtime: node
    plan: free
    nodeVersion: 20
    buildCommand: npm install && npm run build
    startCommand: npm start
    envVars:
      - key: NODE_ENV
        value: production
    autoDeploy: true
```

### 5.2 Build & runtime checks

- `npm run build` already produces `client/dist/`. Verify on a clean checkout.
- Server uses `tsx` at runtime; ensure `tsx` is in `dependencies` (not `devDependencies`).
- `client/src/ws.ts` must build the WebSocket URL with `wss://` when `location.protocol === 'https:'`. Verify or fix.
- The `data/` directory is created on first write. On Render free tier, disk is ephemeral across redeploys — acceptable per parent spec; document in README.

### 5.3 Cold-start note

Render free tier spins down after 15 min idle; first request after sleep takes ~30s. Add a one-line note to README so the first connect attempt isn't mistaken for a bug.

### 5.4 Verification

Manual: push to main, wait for build, three laptops connect to the public URL and play through a full game including end + Новая игра.

## Out-of-scope clarifications
